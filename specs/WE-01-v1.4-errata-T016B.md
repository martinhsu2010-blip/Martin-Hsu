E1 — Two-Layer Geometry and Road Access Interface

Binding requirement.

修訂 v1.4 §C.3、§D.4、§H.2 及 T-016B 的公開介面契約。

E1.1 第一層：geom_valid

每個情境、區域、preset、原型及方向，建立幾何合法中心遮罩 geom_valid。

此遮罩必須檢查：

- 完整地塊位於固定情境多邊形內。
- 原型尺寸及0°／90°方向。
- 完整地塊地形符合 S0。
- 物理支撐完整。
- 不侵占既有障礙物。
- 不侵占保護區。
- 不侵占 Site A。
- 不侵占既有道路及人行道走廊。
- 必要資料完整且可驗證。

geom_valid 不得包含道路接近條件。

未接近既有道路但符合上述幾何條件的地塊，仍須保留於 geom_valid。

不得因道路未連通或缺少道路接近而從第一層遮罩永久移除合法中心。

既有 S1–S3 FOUNDATION_REQUIRED 條件候選及相關原因仍須依原規格保存，但不得混入 S0 的 geom_valid。

E1.2 第二層：Road access evaluation

道路接近判定必須與 geom_valid 分離。

道路接近函式必須接受可替換的走廊清單作為輸入。

沿用 v1.4 R7：

- 距 ROAD ∪ SIDEWALK 外緣 ≤2.0 m。
- 同一地塊邊連續接近長度 ≥8.0 m。
- 不得合併不同地塊邊或不連續片段。
- 圓環不得作為接近依據。
- 不得侵占道路及人行道。
- 道路必須具有符合其驗證狀態的連通證據。

每次判定至少輸出：

- 是否符合道路接近條件。
- 符合條件的地塊邊。
- 接近距離。
- 連續接近長度。
- 對應道路或走廊 ID。
- 道路連通狀態。
- 不符合條件的原因。

T-016B 使用已驗證既有道路走廊計算 C_direct。

未接近合法既有道路的幾何合法地塊，保留 INTERNAL_STREET_REQUIRED。

T-016C／T-016D 可在後續獨立任務中傳入新增走廊，重新執行道路接近判定。

新增走廊不得被當成既有道路，也不得因此直接增加 C_direct。

新增走廊與地塊之間的占地衝突，仍須重新驗證。

E1.3 Minimum public interface

T-016B 至少提供以下公開能力：

1. 固定情境多邊形表。
2. 兩種矩形座標格式的轉換。
3. 單情境、單區域、單 preset 的1 m 遮罩及 prefix sums。
4. 各原型×方向的 geom_valid。
5. 既有道路圖及 AVE_0 主連通分量。
6. 穩定道路 ID。
7. 接受可替換走廊清單的道路接近判定。
8. 確定性貪婪地塊配置。
9. 跨畫質共同配置。
10. 完整資料交接及條件候選原因。

交接資料至少包含：

- schema_version。
- game BASE。
- PHONE_LOW static_fingerprint。
- DESKTOP_HIGH static_fingerprint。
- WE-01A analyzer version。
- T-016B analyzer version。
- polygon_revision。
- 情境及區域。
- 實際地塊清單。
- 條件候選及原因。

公開介面的具體函式名稱、簽章及資料結構，由 Claude 與 Gemini 在 T-016B 登記階段固定。

不得由 Gemini 自行省略上述公開能力。

不得將第一層及第二層合併為不可替換的單一遮罩。

後續 T-016C／T-016D 須能唯讀使用這些介面，不得要求重新實作 T-016B 的核心容量演算法。

E1.4 Regression coverage

沿用 B25、B27、B28、B29、B30 及既有相關 mutation tests，補足以下斷言：

- 幾何合法但缺少既有道路接近的地塊，仍存在於 geom_valid。
- 替換道路走廊清單時，不得改變第一層幾何合法遮罩。
- 合法新增走廊可使原先不符合接近條件的地塊通過第二層判定。
- 新增走廊與地塊重疊時，仍須拒絕。
- 不得因道路接近而忽略地形、障礙物或保護區。
- 不得將尚未建造的走廊計入 C_direct。
- 公開介面必須可由獨立測試匯入及重複使用。

測試必須能捕捉將道路接近條件直接烘入 geom_valid 的錯誤實作。

此測試可整合至既有測試，不強制新增獨立測試檔案。

E2 — ROAD_NET Survey Coverage and Duplicate Segments

修訂 v1.4 §C.1。

E2.1 Data coverage limitation

正式 runtime dump 的道路清單依審計視窗裁切，不代表完整 production ROAD_NET。

依 Claude G0 實測：

- 道路清單共19條原始路段。
- 其中16條為 GROUND。
- 依 v1.4 §C.1 建圖，包含 AVE_0 的主分量有12條原始路段。

上述數量為去重前的原始道路 ID 計數。

以下路段未包含於 dump 內已驗證的主分量：

- HILL_ROAD。
- TRD_0。
- TRD_2。
- SUBR_1。

HILL_ROAD 與 TRD_0 為完全相同的重複路段。

TRD_2 與 SUBR_1 為完全相同的重複路段。

Claude 已確認 production 中部分道路依靠審計視窗外的橫街連接至城市格網。

例如 CRS_360 西端距 HILL_ROAD 起點約5 m，但該橫街不在目前 dump 道路清單內。

此資訊僅用於說明資料覆蓋限制。

不得將未收錄道路硬編碼至分析器。

E2.2 Conservative connectivity rule

若 dump 內的資料無法證明某路段連至 AVE_0 主 GROUND 分量，該路段連通狀態必須為：

UNVERIFIED。

不得推測視窗外道路。

不得將缺少連通證據直接判定為 production 道路實際不連通。

不得將未驗證路段當成合法外部接點。

未驗證路段不得提供 C_direct 所需的道路連通證據。

原 GROUND 連通規則、ELEVATED／RAMP／UNKNOWN 限制及 R7 門檻全部保留。

E2.3 Duplicate segment handling

道路圖建構必須對幾何完全相同的重複路段進行去重，或採用等效的明確重複路段處理。

必須保留原始道路 ID 與去重後代表 ID 的對應關係。

代表 ID 選擇及排序必須確定性。

重複路段不得：

- 重複計入道路面積。
- 重複計入道路連通證據。
- 重複提供道路接近長度。
- 造成同一地塊被重複計數。
- 因別名不同而被視為獨立道路。

報告應區分原始路段數量與去重後的圖節點數量。

E2.4 Impact

依 Claude G0 結果：

- HILL_ROAD／TRD_0 只涉及已知坡度失敗的 H01 起點。
- TRD_2／SUBR_1 只觸及 B3 ENVELOPE 西南角。
- 六條候選道路的既有審查結論不受此資料限制影響。
- REVISED-v2 三區合法土地結果不受影響。

不要求重新擷取 runtime dumps。

不修改 extractor、dump、fingerprints 或 WE-01A 產物。

E2.5 Regression coverage

擴充 B30 及 M-B16 相關測試：

- 缺少視窗外連通道路時，回報 UNVERIFIED。
- 不得補猜缺少的道路連接。
- 完全相同的重複路段不得重複計算。
- 原始 ID 與代表 ID 的對應必須穩定。
- 重複路段不得增加地塊道路接近長度或容量。
- 既有 AVE_0 主連通分量判定維持正確。

Claude 在正式資料驗證階段核對19條原始路段、16條 GROUND 及12條主分量原始路段的證據。

不得將這些正式資料數量硬編碼為通用分析器規則。
